# Dotfiles

Personal dotfiles for Arch Linux + Hyprland (omarchy), deployed with GNU Stow. Each
top-level directory is a **stow package**. The path inside it mirrors the destination
relative to `$HOME` (`claude/.claude/settings.json` → `~/.claude/settings.json`). Required
tools are listed in `readme.md`.

## Stow mechanics

- Run from the repo root: `stow <package>` creates the symlinks, `stow -D <package>` removes
  them, `stow -R <package>` restows (picks up added/removed files).
- **Tree folding**: stow links the highest directory it can own outright — a package whose
  target doesn't exist gets one symlink for the whole tree. When the target already exists as
  a real directory, stow *unfolds* and links each entry inside it individually.
- **The tmux package**: `~/.config/tmux/workspace` is one folded symlink, so the workspace
  tool's `__pycache__` is written inside the repo tree (gitignored).

## The claude package (partially folded — read before adding files)

`~/.claude` is a real directory owned by Claude Code runtime state (history, projects,
plugins), so the `claude` package deploys **per-entry** symlinks: `~/.claude/agents`,
`~/.claude/hooks`, `~/.claude/CLAUDE.md`, `~/.claude/settings.json`,
`~/.claude/statusline-command.sh`. One level deeper, `~/.claude/skills/` is also real (it
hosts the external `omarchy` skill from `/usr/share/omarchy/`), so **each skill has its
own symlink**.

Consequences:

- **A new skill does not deploy itself.** After creating `claude/.claude/skills/<name>/`,
  run `stow -R claude` or link manually:
  `ln -s ../../dotfiles/claude/.claude/skills/<name> ~/.claude/skills/<name>`
- **Drift hazard**: a real (non-symlink) directory inside `~/.claude/skills/` shadows the
  repo and silently diverges. If `ls -la ~/.claude/skills` shows a plain directory, replace
  it with a symlink.
- `claude/.config/dcg` → `~/.config/dcg` is fully folded (one symlink for the directory);
  its runtime file `pending_exceptions.jsonl` lives inside the repo tree but is gitignored.
- `claude/.config/claude-ticket` → `~/.config/claude-ticket` is fully folded. The tmux
  workspace tool symlinks it as `.claude` into every ticket root and loads its `plugin`
  directory as the `ticket` plugin, so a skill added there reaches ticket sessions without
  restowing. Skills must stay under `plugin/`, a `skills/` next to `CLAUDE.md` would load
  a second, unnamespaced copy.

## The omarchy package (partially folded, read before adding files)

`~/.config/omarchy/themed/` and `~/.config/omarchy/hooks/theme-set.d/` are real directories,
omarchy ships its own `.sample` files into both, so the `omarchy` package deploys
**per-entry** symlinks for every `.tpl` and `.hook`.

Consequence:

- **A new template or hook does not deploy itself.** After adding one under
  `omarchy/.config/omarchy/themed/` or `omarchy/.config/omarchy/hooks/theme-set.d/`, run
  `stow -R omarchy` or link it manually. Everything currently in the repo is linked.

## The git package (partially folded)

`~/.config/gh/` is a real directory because `hosts.yml` holds the OAuth token, so `config.yml` is a per-entry symlink. Never add `hosts.yml` to the package.

gh-dash includes the rendered omarchy theme file and a missing include is a hard error, so on a fresh machine apply a theme once before running `gh dash`.

## The opencode package (partially folded, read before adding files)

`~/.config/opencode/` is a real directory owned by OpenCode runtime state (`cli.json`,
`tui.json`, `service.json`, `node_modules`, `package.json`; the database lives under
`~/.local/share/opencode`), so the `opencode` package deploys per-entry symlinks for
`opencode.json` and `AGENTS.md`. The `plugins/` subdirectory is fully folded (one symlink
for the whole directory), so the dcg plugin file lives in the repo tree. A new file added
under `opencode/.config/opencode/` needs `stow -R opencode` to link it.

`opencode.json` mirrors `claude/.claude/settings.json`: the auto-approve allow list, the
deny guards for sudo, destructive git and talosctl commands, and secret-file reads.
`AGENTS.md` is the port of `claude/.claude/CLAUDE.md`. The Claude agents, convention
skills, and the markdown-punctuation hook are not ported yet. The dcg PreToolUse hook is
ported as a plugin.

`plugins/dcg-guard.js` is generated by `dcg install --opencode` and then patched. dcg
0.15.3 emits a `tool.execute.before` check for the `bash` tool, but OpenCode v2 names the
shell tool `shell`, so the guard never fired. The patch accepts both names. `dcg update`
regenerates the file and drops the patch, so re-apply it after upgrading dcg until the bug
is fixed upstream.

## Key files

- `claude/.claude/CLAUDE.md` — global user instructions (orchestration/delegation rules)
- `claude/.claude/settings.json` — permissions, deny list, hook registration
- `claude/.claude/hooks/HOOKS.md` — hook architecture and design rules
- `claude/.config/dcg/config.toml` — destructive-command-guard packs (PreToolUse Bash hook)
- `opencode/.config/opencode/opencode.json` — permissions (allow/deny) and default model
- `opencode/.config/opencode/AGENTS.md` — global OpenCode instructions
- `opencode/.config/opencode/plugins/dcg-guard.js` — dcg PreToolUse plugin (patched for OpenCode v2)
